## 🔴 CRITICAL (14)

### C1. Password dashboard di-embed ke bundle frontend publik (frontend/src/hooks/useApi.jsx:4)
`AUTH = import.meta.env.VITE_DASHBOARD_PASSWORD` → dikirim sebagai `X-Auth` tiap request. Env `VITE_*` selalu di-inline ke `dist/*.js` saat build (terverifikasi dengan build sentinel: string masuk bundle). Siapapun yang buka frontend bisa ekstrak password → **kendali penuh API** (ask, keys, topups, combos, budgets, arm/disarm). Fundamental: auth operasional tidak boleh ada di browser. Build lokal tidak set env (aman), tapi produksi harus set → pasti bocor. **Fix:** sesi/JWT login + cookie, atau Vercel auth-protect agar bundle tak publik.

### C2. CORS `*` ganda (nginx + Flask) + Allow-Headers `*` → CSRF chain (app.py:700, upstream-backend.conf)
Terverifikasi live: POST mutasi dari origin `https://evil.attacker.com` + `X-Auth` valid → **200**, respons bisa dibaca (`Access-Control-Allow-Origin: evil.attacker.com` ×2). Password bukan cookie (jadi belum langsung exploit tanpa leak password), tapi sekali password bocor (C1/R1) → CORS `*` membuat halaman jahat bisa baca respons + kirim mutasi penuh. **Fix:** allowlist origin eksak + hapus header ganda + Allow-Headers eksplisit + sesi/CSRF token.

### C3. **Set harga manual (Asks) masih BROKEN** — C4 audit lama TIDAK benar-benar fixed (Asks.jsx:36-48 + app.py:1961)
Dua cacat: (1) `/api/orderbook` upstream objek tidak bawa `upstream_catalog_model_id` (baris 1961 hanya slug/label/levels/active) → baris 37 selalu `undefined` → return dini; (2) payload PUT tidak kirim `upstream_slug` padahal backend `/api/ask` **wajibkan** (app.py:2117) → 400. Juga kirim `askOutputPerMtok:null` yang ditolak. **Fitur harga manual 100% tidak berfungsi.**

### C4. POST /api/keys & rotate = **500** (app.py:1707-1711, 1725-1726)
Terverifikasi live: `500 {"error":"the query has 7 placeholders but 6 parameters were passed"}` untuk keduanya. INSERT 10 kolom tapi tuple cuma 6 param. **Fitur buat/rotate API key mati total.**

### C5. Dua engine keuangan berbeda profit: workbook $138.53 vs dashboard $247.53 (gen_finance.py vs app.py)
gen_finance amortisasi pro-rata atas semua aset ($104.43) & abaikan refund; app.py amort hanya retired ($45.51) + refund ditambah (+$22.65). Net income beda ~$109. Workbook di-regenerate nightly → **laporan keuangan saling bertentangan.**

### C6. Config auto-pricing: file JSON stale ≠ DB; daemon baca file bukan DB (auto_pricing.py:54, app.py:2239-2250)
Terverifikasi: file 31 baris (codebuddy 13× 10/10, cbcn 8× 10/15, cline-pass 10) vs DB hanya 10 baris (cline-pass). `updated_at` file ISO-string, kode sync tulis float epoch → file BUKAN produksi kode saat ini. Daemon baca file 31 baris → **band codebuddy 10%/10% asing dipakai** → bila ARMED, harga bisa dijual terlalu murah / undercut salah. Edit via dashboard (DB) tak tercermin sampai restart.

### C7. Anti-self-undercut tidak bersih: hanya kurangi provider 'ok' (16), 35 provider invalid kita tetap publikasi ask (auto_pricing.py:335-351)
get_positions kurangi `provider_ok_kita` dari histogram level bawah. Provider `enabled` tapi `apiKeyCheckStatus='invalid'` (35 untuk codebuddy) **masih publikasi ask nyata** (terverifikasi 14 asks @0.74). Bila ask invalid kita di level lebih rendah dari ask valid → daemon anggap kompetitor → undias → **harga turun ke ask sendiri, erosi margin**. (Potensi — saat ini disarm.)

### C8. `/api/history` range bucketing rusak total (app.py:1152-1160, CANDLE_LEN 50-53)
`window = candle_s * MAX_CANDLES` dipakai semua range; `CANDLE_LEN` tidak punya key `7d/30d/90d` → jatuh default 60s → **7d/30d/90d ketiganya identik, cuma 2 jam terakhir**. `24h` = 120 hari. Semua grafik Dashboard/Earnings salah window.

### C9. `/api/earnings-trend` 504 timeout (app.py:1438-1458)
Paginate 300 page `/usage/logs` sinkron per request tanpa cache → curl 30d = 504 (60s nginx timeout). Blokir worker ~60s.

### C10. earning_history terkontaminasi kurva seed sintetis (app.py:317-365, db_seed)
Semua data 05-Jul..08-Agu = kurva linear buatan (840 row, balance konstan 148.83), bukan observasi. `/api/publisher-analytics` mengukur MIN/MAX lifetime → **24h revenue $235 palsu vs real $1.67**. Chart & KPI menyalahkan.

### C11. providers DB = 437 vs live InferHub = 120 (317 stale) (full_sync.py:105-128)
sync upsert-only tanpa delete → provider mati menumpuk. fleet-health/upstreams menampilkan 437 padahal nyata 120; `ok_total` beda antar endpoint (43 cache vs 54 DB). Graf provider overstate 3.6×.

### C12. catalog_models KOSONG (0 row) — bug field 'slug' (full_sync.py:226-245)

### C13. Impairment Momo double-count ($5.38 rugi dua kali) (app.py:489-512 vs 468-484)
Terverifikasi: A-017 (retired, qty2) + A-017a (retired, qty1) = 3 akun Momo $8.07 **sudah masuk amort**. IMP-12 (momo, loss 95898 = Rp2×47949 = $5.38) **masuk impairment juga** — akun yang sama dikurang 2×. Net income tampil $5.38 lebih rendah.
